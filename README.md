# Smart Recruiters Limited — Website

Static, responsive recruitment website for Smart Recruiters Limited (Uganda).

Live site: **https://opoka-eric.github.io/DIZZIE-S-PROJECT/**

## What this is

A front-end only static site: plain HTML, CSS and vanilla JavaScript with no
framework and no build step required to view it. Every page is plain HTML, so the
site works from any static host or from the filesystem.

## Structure

| Path | Purpose |
| --- | --- |
| `index.html` | Homepage (hand written) |
| `*.html` | 21 remaining pages, generated by the scripts in `_build/` |
| `assets/css/style.css` | Design tokens, layout primitives and components |
| `assets/js/data.js` | All content: jobs, services, industries, team, FAQs, process |
| `assets/js/app.js` | Rendering, filtering, forms, navigation, saved jobs |
| `assets/js/icons.js` | Inline SVG icon sprite |
| `_build/` | Page generators and the verification test suite |

## Pages

**Candidate journey** — `find-a-job`, `job-details`, `apply`, `submit-cv`, `job-alerts`
**Employer journey** — `employers`, `submit-vacancy`, `consultation`, `recruitment-process`, `employer-resources`
**Services and company** — `services`, `about`, `industries`, `resources`, `careers`, `ethical-recruitment`
**Support** — `faq`, `contact`
**Legal** — `privacy-policy`, `terms`, `cookie-policy`

## Editing content

All copy, job listings and taxonomy live in `assets/js/data.js`. Change the data
there rather than in the HTML.

The 21 generated pages are produced from `_build/`. To change their markup, edit
the source definitions and regenerate — never edit the generated HTML directly, as
it will be overwritten:

```bash
node _build/build.js
```

## Forms

Forms validate in the browser and save the submission metadata to `localStorage`
under `srl_submissions_v1`. Saved jobs use `srl_saved_jobs`.

**No data is transmitted anywhere.** Uploaded files are read in the browser only to
show the file name and size; file contents are never stored or sent. A backend or
form service is required before the site can receive real enquiries.

CV uploads are validated client side: PDF, DOC, DOCX or RTF only, maximum 5 MB.

## Verification

The `_build` directory contains the test suite. Install Puppeteer first:

```bash
npm install
```

| Command | Checks |
| --- | --- |
| `node _build/build.js` | Regenerate all generated pages |
| `node _build/verify.js` | Internal links, asset references and in-page anchors |
| `node _build/smoke.js` | Renders all 22 pages, plus interaction tests |
| `node _build/contrast.js` | Computed colour contrast against WCAG 2.1 AA |
| `node _build/selects.js` | Confirms every filter select is populated from data |
| `node _build/upload.js` | CV upload type and size validation |

Current status: 22 pages render with no horizontal scroll, 1408 internal references
resolve, all interaction tests pass, and all text meets WCAG AA contrast.

## Accessibility

Colour tokens in `assets/css/style.css` are chosen so that `--teal-600` and darker
clear 4.5:1 both as text on white and as a background behind white text. The lighter
`--teal-400` and `--teal-500` values are decorative only and are never used behind
white text. Interactive targets meet a 44px minimum height.
